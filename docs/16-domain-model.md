# 1. Purpose

This document defines the core business entities of LearnCS and the relationships between them.

The Domain Model represents the business language of the platform.

Every future document, including the Database Design, API Specification, Backend Architecture, and AI Design, will be based on this model.

---

# 2. Core Entities

The LearnCS platform consists of the following core entities:

- Learner
- Domain
- Topic
- Learning Resource
- Assessment
- Question
- Assessment Attempt
- Competency
- Learning Roadmap
- Roadmap Step
- Recommendation
- Learning Session
- Progress
- AI Conversation
- Achievement
- Notification

---

# 3. Entity Definitions

## Learner

Represents a registered user of the platform.

Responsibilities:

- Owns a learning profile
- Takes assessments
- Follows a roadmap
- Studies topics
- Tracks progress
- Interacts with the AI Mentor

---

## Domain

Represents a major field of Computer Science.

Examples:

- Programming
- Data Structures
- Algorithms
- Operating Systems
- Databases
- Networking
- Software Engineering
- Artificial Intelligence

---

## Topic

Represents a single learning concept inside a Domain.

Examples:

- Arrays
- Linked Lists
- Binary Search
- TCP/IP
- SQL Joins

Each Topic belongs to one Domain.

A Topic may have prerequisites.

A Topic may unlock other Topics.

---

## Learning Resource

Represents educational content.

Examples:

- Article
- Video
- Documentation
- Book
- Practice Sheet
- Coding Problem

A Resource can belong to one or more Topics.

---

## Assessment

Represents an evaluation created by the system.

Each Assessment contains multiple Questions.

---

## Question

Represents a single assessment question.

Question types may include:

- Multiple Choice
- True/False
- Coding
- Short Answer

---

## Assessment Attempt

Represents one learner's attempt at completing an assessment.

Stores:

- Answers
- Score
- Completion Time
- Competency Results

---

## Competency

Represents the learner's skill level for a specific Topic.

Examples:

- Beginner
- Intermediate
- Advanced
- Mastered

Competency changes over time.

---

## Learning Roadmap

Represents the personalized learning journey generated for a learner.

Each learner owns one active roadmap.

---

## Roadmap Step

Represents a single Topic inside the roadmap.

Each step has:

- Order
- Status
- Recommendation Reason

---

## Recommendation

Represents a suggestion generated by the Recommendation Engine.

Examples:

- Learn Topic
- Review Topic
- Solve Practice Problems

---

## Learning Session

Represents one study session.

Stores:

- Start Time
- End Time
- Duration
- Studied Topics

---

## Progress

Represents learner progress across the platform.

Examples:

- Completed Topics
- Completed Resources
- Current Roadmap Position
- Completion Percentage

---

## AI Conversation

Represents a conversation between the learner and the AI Mentor.

Stores:

- Messages
- Context
- Suggestions
- Learning History

---

## Achievement

Represents badges, milestones, and rewards earned by learners.

Examples:

- First Assessment
- 7-Day Study Streak
- Completed First Roadmap

---

## Notification

Represents system notifications.

Examples:

- Reminder
- Recommendation Update
- Achievement Earned
- Platform Announcement

---

# 4. Relationships

The relationships between entities are summarized below.

Learner

- has one Profile
- has many Assessment Attempts
- has one Learning Roadmap
- has many Competencies
- has many Learning Sessions
- has many AI Conversations
- has many Achievements
- has many Notifications

Domain

- has many Topics

Topic

- belongs to one Domain
- has many Resources
- has many Questions
- has many Competencies
- has many Recommendations
- may have many Prerequisites
- may unlock many Topics

Assessment

- contains many Questions

Assessment Attempt

- belongs to one Learner
- belongs to one Assessment

Learning Roadmap

- belongs to one Learner
- contains many Roadmap Steps

Roadmap Step

- references one Topic

Recommendation

- belongs to one Learner
- references one Topic

Learning Session

- belongs to one Learner

AI Conversation

- belongs to one Learner

Achievement

- belongs to one Learner

Notification

- belongs to one Learner

---

# 5. Design Principles

The domain model follows the following principles:

- Single Responsibility
- Clear Ownership
- High Cohesion
- Low Coupling
- Extensible Structure
- Technology Independent
- Business-Oriented Design
